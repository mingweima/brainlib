# 威胁模型 / Threat model

## 保护什么 / What is protected

| 风险 | 防线 | 强度 |
|---|---|---|
| AI 助手通过 brainlib 读到私密笔记 | `read`、`find`、`index`、MCP 一律不返回 private 和 secret 笔记；路径越界、符号链接越界被拒 | 硬 |
| 密码、密钥、银行卡号、身份证号被存进库 | 记录和提案内容逐条检查，命中即拒（退出码 3） | 硬（按规则匹配，可能漏掉不常见的格式） |
| AI 擅自改笔记 | 改动只能走提案；L0/L1 每次要用户原话；用户可撤销；每次改动有收据 | 中：AI 可以谎称用户同意，收据会留下它写的原话 |
| AI 读到保险箱 | 用 age 加密；钥匙被用户口令锁住，口令只能在真实终端里输入 | 硬（只要口令不外泄） |
| 日志或报告泄露内容 | 收据、报告只记哈希和数量，`contains_content: false` | 硬 |
| 发布代码或分享库时带出个人信息 | `privacy scan --mode release` 要求私有词表，零命中才放行；放行清单只放行指定文件里的指定短语；git 钩子 | 中（取决于词表是否完整） |
| 同步盘服务商读到笔记 | 私密笔记加密后再同步 | 只保护保险箱里的文件 |

## 不保护什么 / Not protected

- **AI 自己的文件工具。** 能读整个磁盘的 AI，可以绕过 brainlib 直接打开还没加密的文件。对策：私密内容放进保险箱，并按 `templates/agent-permissions/` 在工具层面挡住 `vault/` 和 `private/`。
- **保险箱里的文件名。** 文件名是明文，请起普通的名字。
- **用户自己说出口令。** 口令一旦告诉了 AI，保险箱就等于打开了。
- **被入侵的电脑。** 以本机用户身份运行的恶意程序能读到一切明文。
- **审批的真实性。** `--as human:me` 由 AI 填写，brainlib 无法验证用户是否真的点了头。需要更强保证时，请用户自己在终端里运行 `brainlib review --interactive` 逐条决定。

## 假设 / Assumptions

- 用户的电脑账户只有用户自己能登录。
- age 和 Python 标准库本身可信。
- 状态目录 `~/.brainlib` 只有本机用户能读（POSIX 上权限 700；Windows 上依赖用户目录的默认权限）。
