# 设计取舍 / Design decisions

| 决定 | 理由 |
|---|---|
| 只用 Python 标准库，零依赖 | 用户不需要懂 pip 和虚拟环境；装了 Python 就能跑；macOS 的命令行工具自带的 Python 3.9 也够用 |
| 笔记就是普通 Markdown，文件头可选 | 不绑定任何应用；已有的 Obsidian、Logseq 文件夹直接能用；旧笔记不用改 |
| 状态和输出放在笔记文件夹外面（`~/.brainlib`） | 同步盘和 git 不会带走对话片段和派生文件；笔记文件夹保持干净 |
| 一切改动走提案，附收据和备份 | 用户看得见、能撤销；AI 犯错不会悄悄改坏笔记 |
| 来源六级，推断永远不算用户的观点 | 长期使用后，库里的“我认为”必须真的是用户认为 |
| `brainlib next` 一次只给一步 | 小模型也能照做；不用读完所有文档 |
| 给 AI 的指令用英文，对用户说的话用用户的语言 | 指令格式稳定，任何模型都能解析；用户看到的是母语 |
| 保险箱用 age，钥匙用口令锁住 | 开源、跨平台、成熟；解密必须本人在终端输入口令，AI 无法代劳 |
| 开场 10 道选择题，答案定期复查 | 选择题对普通用户最省力；偏好会变，所以每题都有复查日期和信号机制 |
| 每条记录带说话时间，同一件事以最新的说法为准 | 偏好会变；按说话时间排而不是按记下的时间排，补记的旧话才不会冒充新说法 |
| 字面像的旧行只提示，不自动替换；改主意要 AI 用 `--replaces` 写明 | 字面像不等于改了主意，「熟悉 PyTorch」和「熟悉 JAX」可以同时成立；自动替换被拒时，新说法也会跟着丢 |
| `--replaces` 也认还在缓存区的旧说法 | 用户常常在一次对话里先说一句、过一会儿又改口，两句都还没整理；不认的话两句都会进笔记 |
| 自动更新，每天最多查一次 GitHub 上的正式版，AI 不用先问用户就更新 | 用户装的是一个会跟着规则一起改的工具，旧版本的规则和新文档对不上反而出错；只认官方仓库的正式版，git 只快进，压缩包先核对再备份，用户随时能关 |
| 每条记录也写进当天的日志；笔记页一条记录一条建议 | 日志是按时间记的流水账，笔记页是现在算数的说法；一条一条批，用户可以只收一部分 |
| 说人话的规矩只做中文 | 开发者只要求中文；这些规矩是照中文写作的常见毛病总结的，搬到英文不一定合适 |
